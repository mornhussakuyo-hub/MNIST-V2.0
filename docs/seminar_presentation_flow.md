# MNIST-V2.0 研讨会展示流程

## 一、展示定位

本项目展示的是一个完整的手写数字识别系统：从 MNIST 数据读取、模型训练、模型保存、训练曲线可视化，到服务器上的 Web 手写体验页面，形成一条端到端的机器学习应用链路。

建议开场不要只说“我们做了一个 MNIST 分类器”，而是强调：

> 我们的重点不是简单调用现成深度学习框架，而是用 NumPy / CuPy 从底层实现了 MLP 和 CNN 的前向传播、反向传播、参数更新和部署推理流程。这个项目可以作为后续二值化神经网络推理研究的基础平台。

## 三、展示主线

### 1. 开场：项目要解决什么问题

可以这样讲：

> 我们做的是一个 MNIST 手写数字识别系统。用户可以在网页上画一个数字，后端会把 28 x 28 的像素矩阵送入训练好的神经网络，输出 0-9 每个类别的概率，并给出最终预测结果。

然后补一句项目价值：

> 这个项目的意义在于，我们把机器学习模型从训练到部署的流程完整做通了，并且模型的核心计算不是黑盒调用框架，而是自己实现的，这方便我们后面继续研究更底层的推理优化。

### 2. Web 体验演示

演示动作：

1. 打开服务器部署好的 Web 页面。
2. 在 28 x 28 网格中画一个数字，例如 3、5、8。
3. 点击“开始预测”。
4. 展示右侧最终结果、置信度和 10 个数字的概率柱状图。
5. 清空后再画一个容易混淆的数字，例如 4 / 9 或 3 / 8，展示概率分布变化。

讲解重点：

> 前端并不是上传图片文件，而是直接维护一个长度为 784 的像素数组。用户画出来的每个格子都会变成 0 到 1 之间的灰度值。点击预测时，前端通过 `/api/predict` 把这个数组发给后端，后端加载最新模型并返回分类概率。

如果预测不准，可以自然解释：

> 这也说明了输入分布的重要性。MNIST 原始数据是居中、规范化的手写数字，而网页手写可能存在位置、粗细和尺度差异。所以我们也加入了数据增强脚本，用放大、缩小、平移来提升鲁棒性。

### 3. 数据与训练流程

建议用一条流水线讲清楚：

```text
CSV 数据
  -> 读取标签和 784 个像素
  -> 像素归一化到 0-1
  -> 划分训练集和验证集
  -> 标签 one-hot 编码
  -> 模型训练
  -> 测试集评估
  -> 保存模型 .npz 和训练历史 .npz
  -> 可视化训练曲线
  -> Web 服务加载模型进行推理
```

讲解重点：

> 训练阶段关注的是模型能不能学习；验证集关注训练过程中有没有过拟合；测试集在最后用来评估泛化能力。保存出来的 `.npz` 文件既可以被命令行预测脚本读取，也可以被 Web 服务读取。

### 4. 内部架构讲解

可以分成四层讲：

```text
用户交互层
  web/index.html + web/styles.css + web/app.js
  负责绘图、按钮交互、概率柱状图展示

服务接口层
  scripts/web_app.py
  负责静态页面服务、模型加载、/api/model、/api/predict

模型算法层
  scripts/model.py
  scripts/cnn_model.py
  scripts/cnn_model_gpu.py
  负责 MLP、CPU CNN、GPU CNN 的前向传播、反向传播和参数保存

数据训练层
  scripts/utils.py
  scripts/train.py
  scripts/train_cnn.py
  scripts/train_cnn_gpu.py
  scripts/expand_data.py
  scripts/visualize.py
  负责数据读取、预处理、训练、增强、曲线输出
```

讲 MLP：

```text
784 输入像素 -> 隐藏层 ReLU -> 10 类 softmax
```

讲 CNN：

```text
1 x 28 x 28
  -> Conv1 + ReLU + MaxPool
  -> Conv2 + ReLU + MaxPool
  -> Flatten
  -> Fully Connected
  -> Softmax
```

可以重点解释：

> CNN 版本更适合图像，因为卷积核会在空间上滑动，提取局部笔画特征；池化层降低尺寸，保留更显著的响应。两次 2 x 2 池化后，28 x 28 会变成 7 x 7，最后展开接全连接分类。

### 5. 技术亮点

建议讲 3 个亮点。

第一，手写反向传播：

> 我们没有把训练交给 PyTorch，而是在 `model.py` 和 `cnn_model.py` 里手写了 forward、loss、backward 和参数更新。这让我们能清楚看到梯度是如何从输出层一路传回卷积层的。

第二，im2col 加速卷积：

> 直接写卷积会有很多嵌套循环，效率很低。项目中用了 `im2col`，把图像上的局部窗口展开成矩阵，再把卷积变成矩阵乘法。这样可以利用 NumPy / CuPy 对矩阵乘法的优化。

第三，GPU 加速：

> `cnn_model_gpu.py` 基本保持了 CPU CNN 的结构，但把 NumPy 换成了 CuPy。这样大部分张量计算可以放在 CUDA GPU 上执行，训练时批量更大，速度更快。

### 6. 未来设想：二值化推理 MNIST

核心表达：

> 下一步我们希望研究二值化推理，也就是让网络在推理阶段尽可能使用 0 / 1 或 -1 / +1 进行计算。传统神经网络大量使用浮点乘法，而二值化网络可以把乘法近似替换成位运算，例如 XNOR、popcount、bitcount，从而显著降低计算量和存储量。

可以讲清楚它为什么快：

```text
普通推理：
  float32 权重 x float32 激活
  需要浮点乘加，参数占用大

二值化推理：
  1 bit 权重 x 1 bit 激活
  可以使用位运算统计相同位数量
  参数更小，缓存命中率更高，CPU / FPGA / 边缘设备更友好
```

研究路线建议：

1. 先做权重量化：把训练好的权重从 float32 转成二值权重。
2. 再做激活二值化：把中间层输出也限制到二值。
3. 实现二值卷积推理：用位打包和 bitcount 替代普通矩阵乘法。
4. 比较准确率和速度：记录 float32 CNN、量化权重 CNN、全二值 CNN 的差异。
5. 研究训练策略：直接二值化会掉准确率，需要 Straight-Through Estimator 等方法近似传梯度。

研讨会中可以这样收束：

> 当前项目已经打通了 MNIST 的数据、训练、推理和部署。因为我们掌握了底层 forward / backward 的实现，所以后续可以比较自然地插入量化和二值化逻辑。这也是我们下一阶段想把它从“能识别”推进到“更快、更轻、更适合边缘推理”的原因。

## 五、答辩时可能被问到的问题

### Q1：为什么不用 PyTorch？

可以回答：

> PyTorch 更适合快速工程落地，但这个项目的目标之一是理解神经网络内部机制，所以我们选择用 NumPy / CuPy 实现核心计算。这样更方便解释前向传播、反向传播、梯度更新，也方便未来加入二值化推理这种底层优化。

### Q2：CNN 为什么比 MLP 更适合图像？

可以回答：

> MLP 把 28 x 28 图像直接拉平成 784 维向量，会丢失空间结构。CNN 的卷积核会在局部区域滑动，可以学习笔画边缘、拐角等局部特征，同时通过参数共享减少参数数量。

### Q3：Web 页面输入和 MNIST 原始数据有什么差异？

可以回答：

> MNIST 数据通常是居中、尺度较统一的灰度图，而网页手写可能偏移、过粗、过细或不居中。所以我们用数据增强脚本生成放大、缩小、平移版本，尽量让模型适应更真实的输入。

### Q4：二值化会不会损失准确率？

可以回答：

> 会有可能。二值化的核心取舍是用更低精度换取更快推理和更小模型。我们的研究重点就是比较不同二值化程度下的准确率、速度和模型大小，并探索训练时如何降低精度损失。

### Q5：GPU 版本和 CPU 版本有什么区别？

可以回答：

> 算法结构基本一致，区别主要是计算后端。CPU 版本使用 NumPy，GPU 版本使用 CuPy，把数组和矩阵运算放到 CUDA 设备上执行。保存模型时会再转回 NumPy 格式，方便 Web 服务和其他脚本读取。
